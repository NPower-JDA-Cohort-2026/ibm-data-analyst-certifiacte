## Detailed Notes

### Module 1 — Importing Data Sets
- Each row in a dataset is a record; commas separate values in CSV format.
- To understand a dataset you must analyze the attributes (columns).
- Python data-science libraries are grouped into: Scientific Computing (NumPy, Pandas), Visualization (Matplotlib, Seaborn), and Machine Learning (Scikit-learn). Many are interconnected — e.g. Scikit-learn is built on top of NumPy, SciPy, and Matplotlib.
- `read_csv()` in Pandas reads a CSV file into a DataFrame; the file path and format both matter.
- Pandas has its own dtypes: `object`, `float64`, `int64`, `datetime`. Use `.dtypes` to check them, and correct misclassified types manually.
- `describe()` gives a statistical summary (count, mean, std, min, max, quartiles) for numeric columns by default; use `include='all'` to summarize object-type columns too (adds unique count, top value, frequency).
- `info()` gives a structural overview of the DataFrame (columns, non-null counts, dtypes) — useful for quick inspection.
- `NaN` in a statistical summary means a metric couldn't be computed for that column's data type (e.g. missing values, or non-numeric data).
- Python connects to databases via **SQL APIs** (build SQL text, send via API calls, retrieve results/status) or the **Python DB-API** — the more common standard, using **connection objects** (open/manage connections) and **cursor objects** (run queries, scroll through results). Always close the connection when done to free resources.

**Practice dataset used:** Laptop Pricing dataset (11 parameters: Manufacturer, Category, GPU, OS, CPU_core, Screen_Size_cm, CPU_frequency, RAM_GB, Storage_GB_SSD, Weight_kg, Price) — several categorical fields are pre-mapped to numeric codes (e.g. OS: Windows=1, Linux=2).

#### Cheat Sheet: Importing Data Sets

### Module 2 — Data Wrangling
- Data formatting makes data from different sources consistent/comparable (e.g. converting "city miles per gallon" to "city-litres per 100km").
- Correcting data types ensures accurate statistical analysis downstream.
- **Normalization** makes variable ranges comparable and removes bias introduced by scale differences. Techniques: Feature Scaling, Min-Max, Z-score.
- **Binning** groups continuous data (e.g. "price") into categories to improve model accuracy and visualization; implemented with `numpy.linspace` (bin edges) + `pandas.cut` (assign bins).
- Histograms help visualize the distribution before deciding on bins.
- Most statistical models need numeric input, so categorical variables (e.g. "fuel type") must be converted — typically via **one-hot encoding** with `pd.get_dummies()`.

#### Cheat Sheet: Data Wrangling
| Task | Code |
|---|---|
| Replace missing data with mode | `mode_val = df['attr'].value_counts().idxmax()`<br>`df['attr'].replace(np.nan, mode_val, inplace=True)` |
| Replace missing data with mean | `avg = df['attr'].astype(<type>).mean(axis=0)`<br>`df['attr'].replace(np.nan, avg, inplace=True)` |
| Fix data types | `df[['a1','a2']] = df[['a1','a2']].astype('<data_type>')` |
| Normalize (0–1 range) | `df['attr'] = df['attr'] / df['attr'].max()` |
| Binning | `bins = np.linspace(min(df['attr']), max(df['attr']), n)`<br>`group_names = ['Group1','Group2','Group3']`<br>`df['binned'] = pd.cut(df['attr'], bins, labels=group_names, include_lowest=True)` |
| Rename column | `df.rename(columns={'old':'new'}, inplace=True)` |
| One-hot / indicator variables | `dummy = pd.get_dummies(df['attr'])`<br>`df = pd.concat([df, dummy], axis=1)` |

> [!tip]
> Use the **mean** to fill missing values in a continuous numeric column; use the **mode** (most frequent value) for categorical columns.

### Module 3 — Exploratory Data Analysis (EDA)
- Correlation (`df.corr()` or on selected attributes) measures how strongly variables move together.
- **Pearson correlation coefficient** + **p-value** (via `scipy.stats.pearsonr`) quantify both the strength/direction of a linear relationship and its statistical significance.
- Grouping (`groupby`) and **pivot tables** reorganize data by category to reveal patterns; pseudocolor plots (`plt.pcolor`) can turn a pivot table into a heatmap.

### Module 4 — Model Development
- **Simple Linear Regression (SLR):** relationship between one predictor (x) and one target (y).
- **Multiple Linear Regression (MLR):** one continuous target y, two or more predictors x.
- `regplot`/`residplot` (seaborn) help visually assess strength, direction, and linearity of a relationship; good residuals have zero mean, are evenly scattered around the x-axis, and have consistent variance — patterns in residuals suggest the model needs adjustment.
- For models with multiple features, distribution plots comparing predicted vs. actual values give deeper insight than a single regression plot.
- **Polynomial regression** (`np.polyfit`) fits curves rather than lines; polynomial order affects fit quality.
- Feature transformation (`sklearn.preprocessing`, e.g. `PolynomialFeatures`, `StandardScaler`) prepares data for more accurate models.
- **Pipelines** (`sklearn.pipeline.Pipeline`) chain preprocessing + prediction steps (e.g. scale → polynomial transform → fit model) into one object.
- Model fit evaluation: **MSE** (mean squared error — average squared difference between actual and predicted) and **R²** (proportion of variance in y explained by the model; closer to 1 = better fit). A negative R² can indicate overfitting.

#### Cheat Sheet: Model Development
| Task | Code |
|---|---|
| Create LR model | `from sklearn.linear_model import LinearRegression`<br>`lr = LinearRegression()` |
| Train model | `X = df[['a1','a2']]; Y = df['target']`<br>`lr.fit(X, Y)` |
| Predict | `Y_hat = lr.predict(X)` |
| Coefficient / intercept | `lr.coef_` / `lr.intercept_` |
| Residual plot | `sns.residplot(x=df['a1'], y=df['a2'])` |
| Distribution plot | `sns.distplot(df['attr'], hist=False)` |
| Polynomial regression | `f = np.polyfit(x, y, n)`<br>`p = np.poly1d(f)`<br>`Y_hat = p(x)` |
| Multivariate polynomial | `from sklearn.preprocessing import PolynomialFeatures`<br>`pr = PolynomialFeatures(degree=n)`<br>`Z_pr = pr.fit_transform(Z)` |
| Pipeline | `from sklearn.pipeline import Pipeline`<br>`Input=[('scale',StandardScaler()),('polynomial',PolynomialFeatures(include_bias=False)),('model',LinearRegression())]`<br>`pipe=Pipeline(Input); pipe.fit(Z,y); ypipe=pipe.predict(Z)` |
| R² (linear) | `R2_score = lr.score(X, Y)` |
| R² (polynomial) | `from sklearn.metrics import r2_score`<br>`R2_score = r2_score(y, p(x))` |
| MSE | `from sklearn.metrics import mean_squared_error`<br>`mse = mean_squared_error(Y, Yhat)` |

### Module 5 — Model Evaluation and Refinement
- Split data with `train_test_split()`: train on the training set, evaluate on the unseen test set to measure **generalization error**.
- **Cross-validation:** split data into folds, rotate which fold is used for testing vs. training, average results — useful when data is limited.
- Picking the wrong polynomial order causes **underfitting** (too simple) or **overfitting** (too complex, fits noise); minimize test-set MSE across polynomial orders to choose the best order.
- **Ridge regression** regularizes multiple/polynomial features using hyperparameter **alpha** to reduce multicollinearity-driven overfitting. Determine alpha by training across a range of alpha values on training data, evaluating R² on validation data, and picking the alpha that maximizes R².
- **Grid Search** (`GridSearchCV`) automates hyperparameter tuning: it takes a dictionary of hyperparameter names → candidate values, iterates through combinations using cross-validation, and returns the best estimator.

#### Cheat Sheet: Model Evaluation and Refinement
| Task | Code |
|---|---|
| Train/test split | `from sklearn.model_selection import train_test_split`<br>`y_data = df['target']; x_data = df.drop('target', axis=1)`<br>`x_train, x_test, y_train, y_test = train_test_split(x_data, y_data, test_size=0.10, random_state=1)` |
| Cross-validation score | `from sklearn.model_selection import cross_val_score`<br>`Rcross = cross_val_score(lre, x_data[['a1']], y_data, cv=n)`<br>`Mean = Rcross.mean(); Std_dev = Rcross.std()` |
| Cross-validation prediction | `from sklearn.model_selection import cross_val_predict`<br>`yhat = cross_val_predict(lre, x_data[['a1']], y_data, cv=4)` |
| Ridge regression | `from sklearn.linear_model import Ridge`<br>`pr = PolynomialFeatures(degree=2)`<br>`x_train_pr = pr.fit_transform(x_train[['a1','a2']])`<br>`RigeModel = Ridge(alpha=1); RigeModel.fit(x_train_pr, y_train)`<br>`yhat = RigeModel.predict(x_test_pr)` |
| Grid Search | `from sklearn.model_selection import GridSearchCV`<br>`parameters = [{'alpha': [0.001,0.1,1,10,100,1000,10000]}]`<br>`Grid1 = GridSearchCV(Ridge(), parameters, cv=4)`<br>`Grid1.fit(x_data[['a1','a2']], y_data)`<br>`BestRR = Grid1.best_estimator_`<br>`BestRR.score(x_test[['a1','a2']], y_test)` |

### KDE Plots for Model Evaluation (deep dive)
- KDE (Kernel Density Estimation) plots estimate a probability density function — a smoother alternative to histograms, not sensitive to bin size.
- Used in regression analysis to visually compare the distribution of actual vs. predicted values.
- Seaborn's `distplot` is deprecated; `kdeplot()` is the modern replacement.
- Example workflow: generate/collect data → `train_test_split` → fit `LinearRegression` → predict → plot `sns.kdeplot(y_test, label='Actual', fill=True)` and `sns.kdeplot(y_pred, label='Predicted', fill=True)` on the same axes.
- **Reading a KDE comparison plot:**
  - Overlap between curves = model captures the general distribution well.
  - Peak/mode differences = model may misestimate certain value ranges.
  - Narrower predicted-curve spread than actual = possible underestimation of variance (over-smoothing/bias).
  - Matching tails = model isn't producing extreme outliers beyond the observed data.

## Definitions
| Term | Definition |
|------|------------|
| DataFrame | Pandas' primary 2D labeled data structure (rows + columns) |
| dtype | The data type Pandas assigns to a column (object, int64, float64, datetime, etc.) |
| Normalization | Rescaling variable values (e.g. Min-Max, Z-score) onto a common range to remove scale bias |
| Binning | Grouping continuous values into discrete categories/bins |
| One-hot encoding | Converting a categorical variable into binary indicator columns (`pd.get_dummies`) |
| Pearson correlation coefficient | A statistic (−1 to 1) measuring the strength/direction of a linear relationship between two variables |
| p-value | Probability of observing the data (or more extreme) if there's actually no relationship — used alongside the Pearson coefficient to judge statistical significance |
| R² (R-squared / coefficient of determination) | Proportion of variance in the target variable explained by the model; closer to 1 is better |
| MSE (Mean Squared Error) | Average of the squared differences between actual and predicted values; lower is better |
| Overfitting | Model fits training data (including noise) too closely and generalizes poorly to new data |
| Underfitting | Model is too simple to capture the underlying pattern in the data |
| Cross-validation | Technique that repeatedly splits data into training/testing folds to get a more reliable performance estimate |
| Ridge regression | Regularized regression that penalizes large coefficients via hyperparameter alpha to reduce overfitting from multicollinearity |
| Grid Search | Automated search over combinations of hyperparameter values (e.g. via `GridSearchCV`) to find the best-performing configuration |
| Pipeline (sklearn) | An object chaining multiple preprocessing/model steps so they run sequentially with one `.fit()`/`.predict()` call |
| KDE plot | Kernel Density Estimate plot — a smoothed curve estimating a variable's probability distribution |

## Important Points
- The target/dependent variable is what you're predicting (e.g. "price"); all other columns used to predict it are features/independent variables.
- `df.describe()` defaults to numeric columns only — use `include="all"` to also summarize categorical/object columns (adds unique count, top value, frequency).
- Use the **mean** to fill missing values in continuous numeric columns; use the **mode** for categorical columns.
- Visualize a histogram before deciding on bin boundaries — don't pick bins blindly.
- Residuals should have zero mean and even spread around zero for a well-fitted regression model; a curved/patterned residual plot signals non-linearity or the need for a different model.
- A high R² (close to 1) *and* a low MSE together indicate a good model fit — check both, not just one.
- A negative R² is a red flag, often indicating overfitting.
- Ridge regression is most useful when there's a strong relationship (multicollinearity) among independent variables.
- Grid Search combines hyperparameter tuning with cross-validation to avoid manually guessing the best alpha/hyperparameters.

## Tips & Best Practices
- Say your reasoning out loud when interpreting statistical output (e.g. "R² is 0.85 and MSE is low, so this looks like a good fit") — same habit as coding interview talk-tracks, and useful for the course's project reports.
- Always check `.dtypes` right after importing data — misclassified types (e.g. numbers read as `object`) will silently break later steps like `.mean()` or `.corr()`.
- When comparing actual vs. predicted distributions, prefer `sns.kdeplot()` over the deprecated `sns.distplot()`.
- Build pipelines once your model has more than 1–2 preprocessing steps (scale, polynomial transform, fit) to keep the workflow reproducible.

## Common Mistakes
> [!warning]
> Confusing `df.dtypes` (an attribute — no parentheses) with `df.describe()` — `.dtypes` only shows data types, not summary statistics.

> [!warning]
> Forgetting `include="all"` when you need summary stats for categorical/object columns, not just numeric ones.

> [!warning]
> Using bins without first visualizing the value distribution (histogram) — arbitrary bin edges can hide or distort real patterns.

> [!warning]
> Picking a polynomial order that minimizes *training* error instead of *test* error — this leads to overfitting.

> [!warning]
> Treating a high R² alone as proof of a good model — always check MSE and residual plots too, since R² can be misleadingly high (or misleadingly negative) without those checks.

**Workflow:** Import (Pandas `read_csv`, check `dtypes`/`describe`/`info`) → Wrangle (fix missing values with mean/mode, normalize, bin, one-hot encode) → EDA (`corr()`, Pearson r + p-value, groupby/pivot tables, matplotlib/seaborn plots) → Model (Linear/Polynomial/Multiple regression, Pipelines, judge with R² + MSE) → Evaluate & Refine (`train_test_split`, cross-validation, Ridge regression with alpha, `GridSearchCV` for hyperparameter tuning). ## Interview Questions

### Beginner
1. **Q: What does `df.describe()` return by default, and how do you include non-numeric columns?**
   A: Statistical summary (count, mean, std, min/max, quartiles) for numeric columns only by default; pass `include="all"` to summarize object/categorical columns too.
2. **Q: What's the difference between `df.head()` and `df.tail()`?**
   A: `head(n)` returns the first n rows, `tail(n)` returns the last n rows (default n=5 for both).
3. **Q: Why do you need to convert categorical variables into numeric form before modeling?**
   A: Most statistical/ML models require numeric input; one-hot encoding (`pd.get_dummies`) is the standard technique.
4. **Q: What is the purpose of data normalization?**
   A: To bring variables onto a common scale/range so they're comparable and no single variable dominates a model just because of its scale.
5. **Q: What library/function do you use to read a CSV into a DataFrame?**
   A: Pandas' `read_csv()`.

### Intermediate
1. **Q: How would you replace missing values in a continuous numeric column vs. a categorical column?**
   A: Continuous: replace with the column mean. Categorical: replace with the mode (most frequent value via `value_counts().idxmax()`).
2. **Q: What's the difference between a regression plot and a residual plot, and what does each tell you?**
   A: A regression plot (`sns.regplot`) shows the data + fitted line + confidence interval, indicating linearity/strength. A residual plot (`sns.residplot`) shows the errors; evenly-scattered residuals around zero indicate a good linear fit, while a pattern indicates non-linearity.
3. **Q: Why use cross-validation instead of a single train/test split?**
   A: A single split can give an unreliable performance estimate depending on which rows land in the test set; cross-validation averages performance across multiple folds for a more robust estimate, especially useful with limited data.
4. **Q: What problem does Ridge regression solve, and what does the alpha parameter control?**
   A: It reduces overfitting caused by multicollinearity among features by penalizing large coefficients; alpha controls the strength of that penalty — higher alpha = more regularization.
5. **Q: How do R² and MSE differ as evaluation metrics?**
   A: R² measures the proportion of variance in the target explained by the model (higher/closer to 1 = better); MSE measures the average squared prediction error in the target's own units (lower = better). They're complementary, not interchangeable.

### Advanced
1. **Q: A model has a very high R² on training data but performs poorly on test data. What's happening, and what would you try?**
   A: Classic overfitting — likely too high a polynomial order or too many features relative to data size. Try reducing model complexity, adding Ridge regularization (tune alpha via Grid Search), or gathering more training data.
2. **Q: How would you use Grid Search with Ridge regression to pick the best alpha, and why use cross-validation inside it?**
   A: Define a dictionary of candidate alpha values, pass it plus a `Ridge()` estimator into `GridSearchCV(cv=n)`, and fit on the data; cross-validation inside the grid search ensures each alpha's performance is evaluated across multiple folds rather than one arbitrary split, reducing the risk of picking an alpha that only looks good by chance.
3. **Q: When would you choose Multiple Linear Regression over Polynomial Regression, and what preprocessing step usually pairs with polynomial features?**
   A: Choose MLR when the relationship between features and target is roughly linear; choose polynomial regression when the relationship is curved. Polynomial features are usually paired with `StandardScaler` normalization (often inside a Pipeline) because expanding features to higher-order terms changes their scale.
4. **Q: Interpreting a KDE comparison plot of actual vs. predicted values, what would a narrower predicted-value spread than the actual-value spread suggest?**
   A: The model may be under-estimating variance — a sign of over-smoothing or bias, common in models that are too simple or too heavily regularized.
5. **Q: Why might R² be negative, and what does that indicate?**
   A: R² can go negative when the model performs worse than simply predicting the mean of the target for every observation — a strong indicator of overfitting or a fundamentally poor model/feature choice.
