## 1. Stock Market Concepts (the domain layer)

- A **stock (equity)** = ownership of a small part of a corporation — entitlement to a portion of assets and profits proportional to shares held. Individual units = **shares**.
- Prices update continuously during trading and stream through a **stock ticker**.
- Price drivers: outstanding shares, expectations of future profits (**profit growth** ↑ → price often ↑), and sometimes forces unrelated to performance.

### Short selling (know this cold — great communication-test topic)
Profit from a *decline*: **borrow shares → sell at current price → buy back cheaper → return to lender.** Profit = sell price − buyback price. If the price *rises* instead, losses are potentially unlimited. Used mainly by experienced investors/hedge funds.

**Two real cautionary tales (and the plot of this project):**
- **Tesla** — heavily shorted; profits grew, price surged, shorts lost.
- **GameStop (2021)** — struggling retailer, heavily shorted; Reddit's WallStreetBets drove mass buying, the price exploded **without any revenue improvement**, and short-selling hedge funds took massive losses. A perfect example of price decoupling from fundamentals.

## 2. yfinance — Market Data in Three Lines

```python
import yfinance as yf

tsla = yf.Ticker("TSLA")                 # Ticker object
data = tsla.history(period="max")        # → Pandas DataFrame
data.reset_index(inplace=True)           # Date: index → column (needed for plotting)
data.head()
```

- `.history()` → **DataFrame** of historical market data; key columns: **Open, Close**, High, Low, Volume, Dividends, Stock Splits
- `period` values: `1d 5d 1mo 3mo 6mo 1y 2y 5y 10y` · `ytd` (since Jan 1 of current year) · `max` (everything)
- `.info` → **Python dictionary** of static company facts: `amd.info['sector']`, country, business summary
- Data source: **Yahoo Finance**

## 3. Getting Data Off the Web (recap + project specifics)

Full scraping notes live in [[4.Python for Data Science, AI & Development#6. Module 5 — APIs & Data Collection|Course 4 §6]]. Project-relevant additions:

### Parsers ⚠ (my Q2 miss)
`BeautifulSoup(html, parser)` accepts **`html.parser`**, **`lxml`**, **`html5lib`** (most lenient/robust). **XML and YAML are markup/serialization languages, NOT parsers** — I lost a point marking `xml` as a parser. lxml *can parse* XML documents, but "xml" itself isn't a parser name.

### `pandas.read_html()` — power and limits
```python
tables = pd.read_html(URL)   # → LIST of DataFrames
df = tables[0]               # pick by index — inspect first, the wanted table isn't always [0]
```
Limitations (quiz + real experience):
1. **Only works on `<table>` tags** — anything not marked up as a table is invisible to it (BeautifulSoup remains the general-purpose tool)
2. Some pages store *non-table content* (even images) inside table markup — you get junk tables
3. **Hyperlink text and footnote markers get scraped as data** → post-cleaning required

### HTML tree facts that get tested
- `<tr>` = table **row** · `<td>` = cell · `<th>` = header cell
- `find_all('p')` → **list-like iterable of all matching tag objects** (not just the first, not a string)
- `<head>` and `<body>` both directly inside `<html>` → they are **siblings**

## 4. Cleaning Financial Data (small snippets, big exam value)

```python
# Strip currency symbols AND thousands separators in one pass
df["Price"] = df["Price"].str.replace(',|\$', "", regex=True)

# Dates as datetime, not strings
df["Date"] = pd.to_datetime(df["Date"])
```
- Why datetime matters: **accurate scaling and plotting of time-series data** — string dates sort and space wrongly on axes
- Typical revenue-table cleanup: drop empty/`None` revenue rows, strip `$` and commas, convert to numeric

**Q2. When do you use an API versus web scraping to acquire data?**
> API first, always: structured, documented, stable, and sanctioned — yfinance gave me clean OHLC DataFrames in three lines. Scraping is the fallback for data with no API, like the quarterly revenue tables in my project. It's more fragile — page structure changes break scrapers — and carries legal/ethical obligations: terms of service, robots.txt, rate limits. In the project I deliberately used both, which reflects reality: an analyst's dataset often stitches together sanctioned APIs and carefully scraped public tables.

**Q3. You scraped a revenue table and the numbers look like "$21,461". How do you make them usable?**
> They're strings, so no math works yet. One regex pass removes both offenders: `df["Revenue"].str.replace(',|\$', "", regex=True)`, then convert to numeric with `pd.to_numeric`, and drop or investigate empty rows. Same principle for dates — `pd.to_datetime` — because string dates plot in the wrong order and spacing on a time axis. The general rule: scraped data is text until proven numeric.

**Q4. Why does converting dates to datetime matter for visualization?**
> Because a time axis built from strings is just alphabetical categories — equal spacing regardless of the real gaps, wrong ordering across formats. Datetime gives the plotting library true temporal scale: correct spacing, correct ordering, resampling, and range slicing. In a price-vs-revenue dashboard, the entire insight lives in *when* things happened, so the time axis has to be honest.

**Q5. Your dashboard showed GameStop's price spiking while revenue stayed flat. What's the lesson for an analyst?**
> Two lessons. Analytically: always plot price-type metrics against fundamentals — a single line can look like success, but the *divergence* between two lines is where the story is. Professionally: correlation with fundamentals is the norm, but markets can decouple — GameStop's 2021 spike was a short squeeze driven by retail investors, not performance. An analyst's job is to surface that divergence clearly and resist inventing a fundamentals-based explanation where none exists.

**Q6. Explain short selling to a non-technical stakeholder.**
> You borrow shares and sell them today, hoping to buy them back cheaper later, return them, and pocket the difference — profiting from a fall instead of a rise. The catch: if the price rises instead, there's no ceiling on the loss, because you must buy back at whatever the market demands. That asymmetry is exactly what burned the funds shorting GameStop.

**Q7. What are the limitations of `pandas.read_html()`?**
> It only sees content inside `<table>` tags — brilliant when the data really is an HTML table, blind otherwise. Pages sometimes store non-tabular content in table markup, giving junk results, and it happily scrapes hyperlink text and footnote markers as data, so cleaning is almost always required. It's my first attempt for tables because it's one line; BeautifulSoup is the general-purpose fallback for everything else.

**Q8. Which parser do you use with BeautifulSoup and why?**
> Three real options: `html.parser` (built-in, zero dependencies), `lxml` (fastest), and `html5lib` (slowest but most forgiving of broken HTML — it parses like a browser does). For messy real-world pages html5lib is the robust choice. And a distinction I learned by losing a point on it: XML is a markup language, not a parser — naming precision matters.
