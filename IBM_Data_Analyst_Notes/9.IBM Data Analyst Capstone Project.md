## Key Concepts

- End-to-end analyst workflow: collect → wrangle → EDA → visualize → dashboard → present
- APIs (`requests`, JSON) and HTML scraping (`BeautifulSoup`) as data sources alongside CSV/Excel/SQLite
- Duplicate detection (`df.duplicated()`), uniqueness keys (`Respondent`), and `drop_duplicates()`
- Missing-value strategy: mode for categorical, median for skewed numeric (Age), `fillna`
- Compensation normalization: Yearly as-is, Monthly × 12, Weekly × 52
- Encoding (`LabelEncoder`, `pd.get_dummies`) and scaling (`StandardScaler`, MinMaxScaler 0–1)
- Feature engineering: `NormalizedComp`, age bins with `pd.cut`
- IQR outliers: bounds at Q1 − 1.5×IQR and Q3 + 1.5×IQR; remove extreme compensation before salary trends
- Multi-value survey fields split on `;` then `.explode()` for language/database/tool counts
- Plot families: distribution (hist, box, pie), relationship (scatter, bubble, heatmap), composition (pie, stacked bar), comparison (line, grouped/horizontal bar)
- SQLite as a viz lab store: `to_sql`, `read_sql_query`, close the connection
- Dashboard tabs: current tech, future trends, demographics; submit a **PDF export link**
- Report structure from Haider: cover, ToC, executive summary, intro, lit review, methods, results, discussion, conclusion

Match **Key Skills** and **Location** case-insensitively. Required technologies: C, C#, C++, Java, JavaScript, Python, Scala, Oracle, SQL Server, MySQL, PostgreSQL, MongoDB. Lab example location: New York.

```python
import pandas as pd
import requests

jobs_url = "https://cf-courses-data.s3.us.cloud-object-storage.appdomain.cloud/IBM-DA0321EN-SkillsNetwork/labs/module%201/Accessing%20Data%20Using%20APIs/jobs.json"

def get_number_of_jobs_tl(technology, location):
    response = requests.get(jobs_url)
    if response.status_code == 200:
        jobs_data = response.json()
        number_of_jobs = 0
        for job in jobs_data:
            skills = str(job.get("Key Skills", ""))
            loc = str(job.get("Location", ""))
            if technology.lower() in skills.lower() and location.lower() in loc.lower():
                number_of_jobs += 1
        return technology, number_of_jobs
    return technology, 0

tech, count = get_number_of_jobs_tl("Python", "New York")
print(f"Python jobs in New York: {count}")

technologies = [
    "C", "C#", "C++", "Java", "JavaScript", "Python", "Scala",
    "Oracle", "SQL Server", "MySQL", "PostgreSQL", "MongoDB",
]
job_list = []
for tech in technologies:
    _, num_jobs = get_number_of_jobs_tl(tech, "New York")
    job_list.append({"Technology": tech, "Number of Jobs": num_jobs})

pd.DataFrame(job_list).to_excel("job-postings.xlsx", index=False)
```

**Checklist:** download page HTML → BeautifulSoup parse → scrape language names and average annual salaries → save `popular-languages.csv`.

Page: `https://cf-courses-data.s3.us.cloud-object-storage.appdomain.cloud/IBM-DA0321EN-SkillsNetwork/labs/datasets/Programming_Languages.html`

```python
import csv
import requests
from bs4 import BeautifulSoup

url = "https://cf-courses-data.s3.us.cloud-object-storage.appdomain.cloud/IBM-DA0321EN-SkillsNetwork/labs/datasets/Programming_Languages.html"
webpage_content = requests.get(url).text

scraped_data = []
table = soup.find("table")
for row in table.find_all("tr"):
    cols = row.find_all("td")
    if len(cols) >= 4:
        language_name = cols[1].getText().strip()
        average_salary = cols[3].getText().strip()
        scraped_data.append([language_name, average_salary])

with open("popular-languages.csv", "w", newline="", encoding="utf-8") as file:
    writer = csv.writer(file)
    writer.writerows(scraped_data)
```

### 3. Data wrangling (duplicates, missing values, impute, normalize compensation, encoding, scaling, feature engineering)

**Assignment goals**

- **A.** Identify and remove duplicate rows (integrity).
- **B.** Count missing values per column (completeness).
- **C.** Employment value counts (distribution of work status).
- **D.** Normalize compensation columns such as `CompTotal` and `ConvertedCompYearly` for comparison.

**Finding / removing duplicates (unique steps)**

- Count full-row duplicates: `df.duplicated().sum()`; inspect with `df[df.duplicated(keep=False)]`.
- Uniqueness key used in labs: **`Respondent`** (`df.duplicated(subset=["Respondent"]).sum()` then `drop_duplicates(subset=["Respondent"])` or full-row `drop_duplicates()`).
- Optional: bar chart of duplicate rows by `Employment`.

**Finding / imputing missing values (unique steps)**

- `df.info()`, `df.describe()`, `df.isnull().sum()` (print only columns with count > 0).
- Example column: `WorkLoc` missing count; mode via `df["WorkLoc"].mode()[0]`; `fillna` with that mode.
- Alternate lab column: `RemoteWork` if present, else `WorkLoc`.
- Alternate: `CodingActivities` if present, else `CompFreq`.
- Age: fill with **median** in the combined wrangling lab (`df["Age"].fillna(df["Age"].median())`).
- Visualize Age with `sns.histplot(..., bins=20, kde=True)`.

**Normalizing compensation (canonical function)**

```python
def normalize_comp(row):
    freq = row["CompFreq"]
    total = row["CompTotal"]
    if freq == "Yearly":
        return total
    elif freq == "Monthly":
        return total * 12
    elif freq == "Weekly":
        return total * 52
    return None  # some labs use np.nan

df["NormalizedComp"] = df.apply(normalize_comp, axis=1)
```

Identify compensation columns with `[col for col in df.columns if "Comp" in col]`. Optional hist of `NormalizedComp` with `plt.xlim(0, 200000)` to zoom on the main mass.

**Encoding, scaling, feature engineering (combined wrangling lab)**

```python
from sklearn.preprocessing import LabelEncoder, StandardScaler

label_enc = LabelEncoder()
df["EdLevel_Encoded"] = label_enc.fit_transform(df["EdLevel"].astype(str))
df = pd.get_dummies(df, columns=["Employment"], prefix="Emp", drop_first=True)

scaler = StandardScaler()
df["Age_Scaled"] = scaler.fit_transform(df[["Age"]])

df["Age_Group"] = pd.cut(
    df["Age"],
    bins=[0, 25, 35, 50, 100],
    labels=["Under 25", "25-35", "35-50", "50+"],  # later viz labs use "<25"
)
```

**Canonical wrangling workflow (merged; do once)**

1. `pd.read_csv` the survey URL.
2. Record `len(df)`; `drop_duplicates()` (and/or `subset=["Respondent"]`); print rows dropped.
3. `isnull().sum()` for incompleteness.
4. Impute categorical work/activity columns with **mode**; impute `Age` with **median**.
5. Encode `EdLevel` (label) and `Employment` (one-hot, `drop_first=True`).
6. Scale `Age` with `StandardScaler`.
7. Engineer `NormalizedComp` from `CompFreq`/`CompTotal` and bin `Age_Group`.

> [!tip]
> After `drop_duplicates()`, verify with `df.duplicated().sum() == 0`. Do not use `dropna()` or `isnull().sum()` as a duplicate-removal check.

### 7. Final presentation / report structure

**Course textbook:** *Getting Started with Data Science* — Murtaza Haider, IBM Press, 1st edition (13 Dec 2015). Prescribed reading: **Chapter 3, pp. 60–62**.

#### Brief vs detailed reports

Structure depends on length. A **brief** report (five or fewer pages) is to the point and summarizes key findings. A **detailed** report (possibly 100+ pages) builds the argument incrementally: related work, methodology, data sources, intermediate findings, and main results.

Consultant practice (Deloitte, McKinsey, as described in the reading): length follows purpose. Brief reports comment on current trends that attract public or media attention. Comprehensive reports critically review the subject with extensive analysis; they often collect new data or interview industry experts.

Even a short deliverable should follow a prescribed format: **cover page, table of contents, executive summary, detailed contents, acknowledgments, references, and appendices** (if needed).

#### Cover page

Often missing — including in undergraduate, doctoral, and business reports. Minimum:

- Title
- Author names, affiliations, and **contacts** (make it easy to reach the authors)
- Institutional publisher (if any)
- **Date of publication** (needed for citation)

#### Table of contents

A ToC is a map of the document: main headings plus lists of tables and figures. Include one especially if the body (excluding cover, ToC, and references) is **five or more pages**. Do not skip it for longer work.

#### Abstract / executive summary

Recommended even for short documents: the crux of the argument in **three paragraphs or less**. For documents of a few hundred pages, the executive summary can be longer.

#### Body sections (recommended order)

1. **Introduction** — set up the problem for a reader new to the topic.
2. **Literature review** — length depends on how contested the topic is. If most researchers agree, cite the most influential work briefly. If arguments are nuanced, give adequate context. Use this section to highlight **knowledge gaps**, then state **research questions and hypothesis**.
3. **Methodology** — methods and data sources. If you collected new data, describe that exercise. Tie variable/data/method choices back to the literature and to the research questions.
4. **Results** — start with descriptive statistics and illustrative graphics, then formal hypothesis tests. Statistical models may include regression or categorical analysis; time-series and data-mining techniques are referenced to later textbook chapters. Business reports often hold back statistical detail and summarize with graphics.
5. **Discussion** — narrative that lets the numbers communicate the thesis. Return to the research question and gaps; show how findings fill them. Results may only partly answer the question, often with caveats.
6. **Conclusion** — generalize findings; do not leave the reader stuck only in caveats; identify future research and applications.
7. **Housekeeping** — references, acknowledgments (credit those who enabled the work), appendices.

Textbook cross-references in the reading: Ch. 4 tables; Ch. 5 plots; Ch. 10 maps; Ch. 6 hypothesis testing; Ch. 7 regression; Ch. 8–9 categorical data; Ch. 11 time series; Ch. 12 data mining.

#### Writer’s job (Transport Policy checklist, reproduced in the reading)

As a data scientist you analyze with appropriate data and tools; as a writer you communicate findings. Before treating the report as done, check:

- Have you told readers, at the outset, what they might gain by reading your paper?
- Have you made the aim of your work clear?
- Have you explained the significance of your contribution?
- Have you set your work in the appropriate context by giving sufficient background (including a complete set of relevant references)?
- Have you addressed the question of practicality and usefulness?
- Have you identified future developments that might result from your work?
- Have you structured your paper in a clear and logical fashion?

## Definitions

| Term | Definition (as used in this course) |
|---|---|
| Data wrangling / munging | Cleaning and preparing datasets so they are ready for analysis |
| API | Interface for retrieving data programmatically; this course uses HTTP GET + JSON via `requests` |
| Web scraping | Downloading HTML and extracting structured fields (here: table cells with BeautifulSoup) |
| Duplicate row | A repeated observation; full-row or key-based (`Respondent`) |
| Mode imputation | Filling missing values with the column’s most frequent value (`mode()[0]`) |
| Compensation normalization | Converting `CompTotal` at Yearly / Monthly / Weekly frequency into a comparable annual amount |
| Label encoding | Mapping categories to integers (`LabelEncoder` on `EdLevel`) |
| One-hot encoding | Binary dummy columns (`pd.get_dummies` on `Employment`, `drop_first=True`) |
| StandardScaler | Feature scaling to mean 0, variance 1 (applied to `Age`) |
| MinMaxScaler | Scales a column to a range, usually **0 to 1** |
| Feature engineering | Creating new columns from existing ones (`NormalizedComp`, `Age_Group`) |
| IQR | Interquartile range: Q3 − Q1 (spread of the middle 50%); outliers beyond Q1 − 1.5×IQR and Q3 + 1.5×IQR |
| Cross-tabulation | Frequency table of two categoricals (`pd.crosstab`) |
| Augmented analytics | AI/ML that automates preparation, insight discovery, and explanation |
| AutoML | Tools that simplify model creation for non-specialists |
| Executive summary | Short front-matter statement of the argument (three paragraphs or less on brief reports) |

## Important Points

- Collection sources for the capstone scenario: job postings, training portals, Stack Overflow Developer Survey.
- `requests` downloads pages and calls APIs; BeautifulSoup parses HTML; **pandas** loads/manipulates tabular data; `csv.writerow` / `writerows` write CSV; `<tr>` is an HTML table row.
- JSON job listings use a `.json` URL pattern (quiz example: `/positions.json`), not `.xml` / `.csv` / `.html`.
- After downloading Jobs_API, **upload the file to the lab** and run it there.
- Multi-select survey answers are semicolon-separated; split and explode before counting.
- Identifying duplicates exists to keep analyses **accurate and unbiased**, not to enlarge the data or improve chart aesthetics.
- `df.describe(include="all")` summarizes **all** columns including categoricals; `df.describe()` is the numeric summary (mean, count, std, min, max).
- `df.isnull().sum()` is the missing-value census per column.
- `sns.countplot` is the go-to for a **categorical** distribution; histograms suit continuous fields such as `YearsCodePro`.
- Best practice in this course for extreme compensation outliers when analyzing **average** pay: **remove** them so central tendency is not skewed; purpose is common salary values and less skew, not a higher median for its own sake.
- Filter **full-time** employees first, then take the median of `ConvertedCompYearly`.
- Close SQLite connections when a viz lab part is finished.
- Dashboard purpose: **visualize and analyze**, not store raw data or share unprocessed files.
- Line charts: continuous data over time (or age as a timeline-like axis — age groups on the **X-axis**). Grouped bars compare several categories side by side.
- Pie charts suit proportions (quiz example: distribution by gender). Tree maps suit hierarchical platform-desire data.

## Tips & Best Practices

- Prefer **mode** for categorical missing values and **median** for Age in the combined wrangling lab (Age is numeric and often skewed).
- Recheck duplicates with `df.duplicated().sum()` after dropping; do not confuse that check with `dropna()` or `isnull()`.
- When schemas differ, pick columns with `if col in df.columns` fallbacks rather than assuming 2024 names exist on `m1_survey_data.csv`.
- For compensation histograms, zoom (`xlim` to ~$200k or the 95th percentile) so a few extreme salaries do not flatten the plot.
- Filter nulls in dashboards so charts show valid data.
- Always title charts and label values so stakeholders can read the visual without guessing.
- Put contact details and a publication date on the report cover; include a ToC once the body is about five pages or more.
- Open the report by telling the reader what they gain; close by stating usefulness and future work (Transport Policy checklist).

   **A:** `df.duplicated().sum()`.

4. **Q: How should you fill missing values in a categorical column such as `WorkLoc` or `RemoteWork` in these labs?**  
   **A:** With the mode: `df['column'].fillna(df['column'].mode()[0])`.

5. **Q: What three tabs did the capstone dashboard require?**  
   **A:** Current technology usage, future technology trends, and demographics.

### Intermediate

1. **Q: How do you turn `CompFreq` and `CompTotal` into a comparable annual compensation?**  
   **A:** Yearly = total; Monthly = total × 12; Weekly = total × 52; store as `NormalizedComp`.

2. **Q: How does this course detect compensation outliers, and what do you do with them before salary-trend analysis?**  
   **A:** IQR: Q1/Q3, bounds at ±1.5×IQR; drop rows outside the bounds so typical salaries are not skewed.

3. **Q: Survey language and database fields contain multiple values. How do you count popularity?**  
   **A:** `dropna()`, `str.split(";")`, `.explode()`, then `value_counts()`.

4. **Q: After `drop_duplicates()`, how do you prove duplicates are gone?**  
   **A:** Re-run `df.duplicated().sum()` and confirm it is zero — not `dropna()` or `isnull().sum()`.

5. **Q: What chart types map to current vs future platform fields on the dashboard?**  
   **A:** `PlatformHaveWorkedWith` → word cloud; `PlatformWantToWorkWith` → tree map.

### Advanced

1. **Q: The documented survey schema uses `ConvertedCompYearly` and `LanguageHaveWorkedWith`, but labs load `m1_survey_data.csv`. How should code stay robust?**  
   **A:** Detect columns at runtime (e.g. yearly comp vs `ConvertedComp`, languages vs `LanguageWorkedWith`, `RemoteWork` vs `WorkLoc`) and use the name that exists.
