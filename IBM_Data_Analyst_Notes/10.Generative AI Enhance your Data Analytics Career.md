## Key Concepts

- **Generative AI** creates new, synthetic data (unlike traditional models that only predict or classify).
- **Data augmentation** artificially grows a training set by creating modified data from existing data; GenAI can also generate entirely new points that resemble existing data.
- GenAI can address **limited / unbalanced data**, automate **prep** (imputation, anomaly detection, normalization), turn **natural language into SQL**, surface **hidden patterns**, generate **visuals**, and draft **data stories**.
- **Q&A for data** uses machine learning and NLP to interpret questions about a dataset and return relevant answers.
- **Microsoft 365 Copilot** combines large language models (LLMs) with Microsoft Graph data inside Word, Excel, PowerPoint, Outlook, and Teams.
- **IBM watsonx** is presented as a data-analytics platform spanning collection, prep, EDA, ML, real-time analytics, explainable AI (XAI), collaboration, and deployment. NatWest’s “Marge” (Watson Assistant on IBM Cloud) is the flagship case study.
- **Responsible AI** (also called ethical or trustworthy AI) rests on IBM’s five pillars: Explainability, Fairness, Robustness, Transparency, Privacy.
- **Hallucination** = inaccurate or illogical GenAI output, attributed here to flawed training data, inappropriate model architectures, and inadequate evaluation.
- Human oversight still matters: silent logical errors, hallucinated syntax, context blindness, and data privacy (do not paste raw sensitive data into public LLMs).

## Detailed Notes

### Starting-point reflection (Samir)

Experience using GenAI for analytics: writing SQL, troubleshooting Python (pandas, Scrapy), cleaning datasets, and generating machine learning study outlines. It is a multiplier for syntax fixes and exploratory analysis **if edge cases are double-checked**.

**Limitations that still need manual oversight**

- **Silent logical errors (the biggest risk, not syntax):** queries with `GROUP BY` and `JOIN`s can run with no syntax error yet miscalculate aggregations because of duplicate records or bad join conditions.
- **Outdated / hallucinated syntax:** pandas and scraping libraries (Scrapy, Selenium) change quickly; models suggest deprecated APIs or invent parameters.
- **Context blindness:** the model does not know domain rules, missing-value policy, custom KPIs, or skewed distributions unless told.
- **Data privacy:** raw, unmasked, or sensitive data must not be pasted into public LLM interfaces.

**Learning focus:** reliable AI-augmented pipelines — complex SQL aggregations, scraping scripts, and feature engineering — shrinking cleaning/EDA from hours to minutes **without** hidden logical errors or corrupted distributions.

**Evaluation process and success metrics (keep this)**

1. Tests and sanity-check queries for **every** transformation or aggregation before it enters a pipeline.
2. **Velocity:** cut time spent writing initial boilerplate ETL/cleaning scripts by 50%+ without increasing later debug time.
3. **Data integrity:** zero silent logical errors (duplicate row counts after a JOIN, skewed summary statistics, dropped missing values) reaching final analysis.

**Session strengths:** advanced grasp of GenAI’s capabilities *and* pitfalls (logical errors, context blindness); practical, measurable goals (velocity + data integrity). Continue applying that evaluation process and using messy, unstructured data (e.g. scraped real estate or regional economic data) to stress-test cleaning and feature-engineering prompts.

### GenAI across the analytics lifecycle

Data analytics here = gathering, cleaning, analyzing and mining data, interpreting results, and reporting findings.

GitHub (cited in the analytics-process reading): developers using GitHub Copilot — **88%** more productive; **96%** faster with repetitive tasks.

#### 1. Data generation and augmentation

Create new points that resemble existing data. Addresses incomplete or unbalanced datasets.

- More diverse, representative training data → more robust, generalizable ML models
- Less impact from data scarcity and bias → better statistical analysis and predictive modeling
- Hypothetical scenarios and simulations → outcomes and risks

**Augmentation tools named in the Module 1 summary:** CTGAN, SDV, GauGAN, Imagen, StyleGAN2, BigGAN, SoundGAN.

- **Structured data:** CTGAN, SDV
- **Images (high-resolution / realistic):** StyleGAN2, BigGAN (also GauGAN, Imagen)
- **Audio:** SoundGAN

**DataRobot** uses GenAI to augment datasets by creating synthetic points for more diverse training data.

#### 2. Data preparation

Cleaning, transforming, and organizing data so it is analysis-ready. GenAI can automate:

- **Imputation** — fill missing values
- **Anomaly detection** — find and correct outliers/errors
- **Normalization** — standardize formats and scales

**Data manipulation tasks listed:** replace missing values, manage outliers, apply filters, merge tables, delete columns, generate CSV files, query specific data, find rows, replace values, sort tables, insert new rows, create sub-tables.

#### 3. Querying databases

Natural language → SQL; auto-generate optimized SQL; real-time responses for interactive exploration. Course claim: GenAI can formulate complex queries, optimize database interactions, and adapt to evolving data structures.

#### 4. Insights

- Hidden patterns and correlations
- Hypotheses and explanations for observed trends
- Personalized insights for a user or context

#### 5. Visualization

- Creative, appealing charts that capture the data
- Adapt visuals to different audiences
- Interactive / immersive exploration

#### 6. Storytelling

- Narratives that summarize key findings
- Anecdotes, trends, and outliers as story elements
- Tone and style matched to the audience
- Cohesive structure; highlight key insights

**Benefits listed:** better data quality; better model performance from richer training data; faster insight generation; hidden patterns; personalized insights.

**Ethics (lifecycle reading):** privacy, fairness, and transparency. Models should be trained and deployed on data handled with care. Salesforce survey cited: **over 70%** of IT directors worry that “Generative AI will introduce new security risks to our data.”

### Responsible Generative AI for data professionals

GenAI (including GPT-3 / GPT-4) brings **bias and fairness**, **ethical use**, **explanation**, **privacy**, and **environmental impact** challenges.

**Responsible AI** (ethical / trustworthy AI): debiasing, diverse dataset curation, continuous monitoring for biases.

**IBM’s five pillars:** Explainability, Fairness, Robustness, Transparency, Privacy.

Practices named: transparency and accountability; hold developers, organizations, and systems accountable; ethical guidelines and industry standards; research on interpretability and explanations; **federated learning** and **differential privacy**; collaboration among researchers, ethicists, policymakers, and the public; user empowerment and education; user control over AI systems.

**Legal and regulatory compliance:** follow existing laws; responsible-AI practice can also shape future regulation.

**Social impact:** prevent harm; respect human rights; fair treatment; inclusive design; avoid discrimination; promote diversity; sustainable / eco-friendly research and deployment. Unethical practice risks public backlash, legal action, and restrictions that threaten long-term viability.

Practices recap: transparency about capabilities and limits; inclusive training data; stakeholder input; continuous monitoring; collaboration; user empowerment; education; legal/regulatory compliance; advocate for responsible-AI legislation.

### Case study: GenAI in healthcare — considerations

A healthcare data team used GenAI for augmentation, diagnostics, drug design, and personalized care. Each area had distinct issues and responses.

#### Data augmentation

| Issue | Response |
|---|---|
| Data quality and relevance | Rigorous quality control; external sources for integrity |
| Data diversity (avoid overfitting) | Models that capture original diversity; **adversarial training** for diverse patterns |
| Privacy | **Federated learning** and **differential privacy** so data can be shared without exposing patients |

**Approach:** evaluate generated data so it keeps original statistical properties (no artificial bias/distortion); collaborate with clinicians/researchers for clinical relevance.

#### Diagnostics

| Issue | Response |
|---|---|
| Diverse sources (images, history, labs) | Harmonization and integration frameworks |
| Trust | Explainable AI: **saliency maps** and **LIME** (Local Interpretable Model Explanations) |
| Reliability | Clinical trials vs traditional diagnostic methods |

**Approach:** curate datasets to reduce diagnostic bias; continuously monitor and update models as data and clinical practice change.

#### Drug design

| Issue | Response |
|---|---|
| Molecular complexity and dynamics | GenAI that represents and simulates structures and interactions |
| Target specificity and efficacy | Design candidates that hit disease molecules without harming healthy cells |
| Side effects before trials | Predictive models and **virtual screening** |

**Approach:** partner with pharma and research labs for relevant molecular data; optimize models to cut compute time.

#### Personalized healthcare

| Issue | Response |
|---|---|
| Privacy and security | Transparent governance, security measures, clear patient communication |
| Individual preferences | Involve patients in designing AI tools |
| Clinical use | Explainable recommendations so clinicians keep decision authority |

**Approach:** evaluate models for unfair/discriminatory recommendations; **human–AI collaboration** — recommendations in the workflow with clinician oversight. AI should **complement, not replace**, clinical expertise.

## Important Points

- GenAI’s headline analytics use is **creating synthetic / augmented data**, including **filling missing points** and growing small or imbalanced sets — not generating music or images as the “most accurate” analytics application (final exam).
- **RapidMiner** = DS/ML platform with GenAI for predictive modeling **and** augmentation. **Tableau** = viz + NL queries / automated prep. **DALL-E 2** is described as **unavailable to the public** in this course.
- Palantir AIP = secure LLM infrastructure, data access, and auditing. Alteryx **AiDIN** = GenAI + ML on Alteryx Analytics Cloud.
- Insights ≠ storytelling ≠ prep ≠ querying. Insights = hidden patterns, hypotheses, personalized insights. Prep = imputation, anomalies, normalization. Querying = NL → SQL. Viz = creative / audience-adapted / interactive charts. Stories = narrative elements and structure.
- Q&A for data = ML + NLP to **comprehend questions and return relevant answers** — not predicting future question trends or “latent codes.”
- Copilot in Excel: **natural language queries** → correlations and new formulas; **model generation** → trends and charts.
- Healthcare: preserve statistical **fidelity** of synthetic data; use **XAI** (saliency maps, LIME) in diagnostics; AI **augments** clinicians.
- Technical vs organizational vs cultural challenges are tested separately (standardization and compute cost = technical; change management = organizational).
- Course SQL quizzes sometimes omit parentheses in `COUNT *`; production SQL is `COUNT(*)`.

- **NatWest / Marge:** Watson Assistant on IBM Cloud inside existing mortgage data; +20% NPS, −10% call duration; keyword console for agents.

## Tips & Best Practices

**Samir’s evaluation process for AI-generated code**
1. Never merge AI SQL/Python into a pipeline until **tests and sanity-check queries** pass.
2. After JOINs: compare row counts to grain you expect (watch duplicates).
3. After aggregations: compare summary statistics to known baselines (watch skew and dropped missings).
4. Track **velocity** (boilerplate ETL time down ≥50% without more debug later) and **integrity** (zero silent logical errors in final analysis).
5. Prefer messy, real data (scraped real estate, regional economic data) when practicing — missing values, odd formats, and duplicates expose bugs syntax checks miss.
6. Do not paste **raw/unmasked/sensitive** data into public LLMs.

**Course prompting**
- Name the **artifact** (bar chart, SQL, Python), the **metric** (count, average), and the **slice** (by area, column name).
- For missing values, say the **language** and the **fill method** (e.g. Python, column mean) and whether to save the updated file.
- For viz, specify plot type and the exact attributes vs the target.

**Responsible use**
- Debias, diversify training data, monitor continuously.
- Use XAI (LIME, SHAP, Captum, saliency maps, feature attribution) when decisions affect people.
- Federated learning / differential privacy for sensitive domains.
- Keep a **human in the loop** (clinician, analyst, domain expert).

## Common Mistakes

> [!warning] Silent logical errors look like success
> AI SQL can `JOIN`/`GROUP BY` without a syntax error and still double-count or mis-aggregate. Validate grain and totals, not just “it ran.”

> [!warning] Hallucinated or deprecated APIs
> pandas, Scrapy, and Selenium change; models invent parameters. Check current docs before running generated code.

> [!warning] Context blindness
> Missing-value rules, custom KPIs, and skewed distributions are not inferred. Put them in the prompt or the model will guess.

> [!warning] Privacy
> Public LLM UIs are not a place for unmasked production data. Course + Salesforce: GenAI is widely seen as a new security risk.

> [!warning] Vague prompts
> “Create a chart” or “Create a bar chart that shows sales by area” loses to a prompt that includes **average** (or the aggregation you actually want).

> [!warning] Mixing lifecycle jobs
> Anomaly detection is **prep**; hidden patterns are **insights**; narratives are **storytelling**; NL→SQL is **querying**. Exam items punish mixing these.

> [!warning] Confusing univariate / bivariate / multivariate
> One attribute = univariate; any pair = bivariate; pair plot of **all** pairs = multivariate.

> [!warning] Tool mix-ups
> DataSquirrel = clean + GDPR dashboards, not “GPT-4 charts via prompt engineering.” DesignerBot = docs/PDFs/URLs → slides, not conversational narrative editing. Crystal = iGenius conversational link between business and data teams — not the “embeddable analytics conversational chat service” item (that question’s correct choice is not marked in this dump).

> [!warning] Hallucinations
> Treat fluent output as untrusted until evaluated. Course cause: flawed training data (also architecture and evaluation).

## Interview Questions

### Beginner

1. **Q: What is generative AI, as this course defines it?**  
   A: AI that **creates new, synthetic data**, rather than only predicting or classifying existing data.

2. **Q: What is data augmentation?**  
   A: Artificially increasing a training set by creating **modified data from existing data**. GenAI can also generate new points that resemble the original distribution.

3. **Q: Name three ways GenAI can help in data preparation.**  
   A: **Imputation** (fill missings), **anomaly detection** (outliers/errors), **normalization** (standardize formats and scales).

4. **Q: What does Microsoft 365 Copilot combine, and where does it show up?**  
   A: **LLMs + Microsoft Graph** data, inside Word, Excel, PowerPoint, Outlook, and Teams (plus Business Chat).

5. **Q: What are IBM’s five pillars of responsible AI?**  
   A: **Explainability, Fairness, Robustness, Transparency, Privacy.**

### Intermediate

1. **Q: How does GenAI change database querying for analysts and non-technical users?**  
   A: Natural-language questions become SQL; queries can be auto-generated and optimized; responses can run in real time. The course also claims it can adapt to evolving data structures.

2. **Q: Walk through the NatWest / watsonx mortgage case at a high level.**  
   A: NatWest and IBM built **Marge** (Watson Assistant on IBM Cloud) inside existing mortgage data so agents get real-time policy answers. Reported impact: **+20% NPS**, **−10% call duration**.

3. **Q: What is Q&A for data, and name frameworks this course lists?**  
   A: Using **ML and NLP** to interpret questions about a dataset and return answers. Named: Cognos Analytics, Power BI, Tableau Pulse, ThoughtSpot, Analytics Chatbot, Dash Enterprise, Crystal.

4. **Q: What is an AI hallucination, and what causes does the course list?**  
   A: Inaccurate or illogical generated information. Causes: **flawed training data**, inappropriate model architectures, inadequate evaluation.

5. **Q: How would you prompt Copilot in Excel vs PowerPoint?**  
   A: Excel: NL analysis (“Give sales breakdown,” “generate a chart,” “Analyze and summarize the data”). PowerPoint: “Create presentations from documents,” “consolidate presentations,” “reformat content.”

### Advanced

1. **Q: Why are silent logical errors more dangerous than syntax errors in AI-generated SQL?**  
   A: `JOIN`/`GROUP BY` can execute cleanly while **duplicating grain** or mis-aggregating. Oversight needs row-count and summary-stat checks, not just a green run.

2. **Q: How should a healthcare team use GenAI for data augmentation without leaking patient data or distorting clinical reality?**  
   A: Quality control and diverse generation (e.g. **adversarial training**); **federated learning** and **differential privacy**; validate that synthetic data keeps original **statistical properties**; involve clinicians.

3. **Q: Contrast data, model, and ethical considerations with an industry example each.**  
   A: **Data** — retail purchase history, specs, trends, social; **model** — explainability from architecture/training, interpretability via **feature attribution** / partial dependence; **ethical** — no public-opinion manipulation; finance bias checks with **fairness metrics**.

4. **Q: You need synthetic faces for a recognition model, structured tabular boost, and a secure place to run LLMs. Which tools does this course point to?**  
   A: Faces: **StyleGAN2** (and StyleGAN). Structured: **CTGAN** / **SDV**. Secure LLM ops: **Palantir AIP**.

5. **Q: How would you evaluate AI-generated ETL before it reaches production analysis?**  
   A: Tests and sanity queries on every transform; JOIN duplicate checks; distribution/summary-stat checks; missing-value policy; never paste raw PII into public models. Success = **velocity** (boilerplate time down) **and** **zero silent integrity bugs**.
