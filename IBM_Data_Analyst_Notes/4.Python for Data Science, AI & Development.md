## 2. Module 1 — Python Basics

### Types & casting
- Core types: `int`, `float`, `str`, `bool` · `1.0` → **float** (decimal point decides)
- Casting: `int(3.99)` → 3 (truncates) · `int("1")` → 1 · `str(1)` → "1" · `bool(1)` → True
- `type(x)` reveals the type

### Expressions ⚠ (my final-exam miss lives here)
| Operator | Meaning | Example |
|---|---|---|
| `/` | **True division — always float** | `1/2` → **0.5** · `2/1` → 2.0 |
| `//` | **Floor division — rounds down** | `1//2` → **0** · `2//1` → 2 |
| `%` | Modulo (remainder) | `7%3` → 1 |
| `**` | Exponent | `2**3` → 8 |

> [!warning] Final exam Q3 (my only miss — 19/20)
> *"Which code outputs 0.5?"* → **`1/2`** (true division). I mixed up `/` vs `//` under time pressure. Floor `//` **discards** the fractional part; `1//2` = 0, not 0.5. Ten years of Python and the exam still got me on the basics — never coast on "easy" questions.

### Strings
- Sequences: indexing `Name[0]`, negative indexing `Name[-1]`, slicing `Name[0:3]`, **stride** `Name[::2]` (every 2nd char)
- Immutable — methods return **new** strings: `.upper()`, `.lower()`, `.replace(old,new)`, `.find(sub)` (→ **index of first match**, `-1` if absent), `.split(delim)`, `len()`
- Escape sequences: `\n` newline, `\t` tab, `\\` backslash · **Raw strings** `r"C:\new\folder"` disable escapes (file paths, regex)
- Concatenate `"a"+"b"`, replicate `"ab"*3`

### Formatting (3 ways, oldest → newest)
```python
"Name: %s, Age: %d" % (name, age)      # % operator (legacy)
"Name: {}, Age: {}".format(name, age)  # str.format()
f"Name: {name}, Age: {age + 1}"        # f-string ⭐ — evaluates expressions inline
```

## 3. Module 2 — Data Structures

### Lists vs. Tuples ⭐
| | List `[ ]` | Tuple `( )` |
|---|---|---|
| Mutable | ✅ yes | ❌ no (immutable) |
| Use when | contents change | fixed records, dict keys, safety |
| Methods | append, extend, insert, remove, pop, sort, reverse | count, index (+ len, sum, min, max, sorted) |

### append vs extend ⚠ (practice-quiz miss)
```python
L = [1, 2]
L.append([3, 4])   # → [1, 2, [3, 4]]   one element (the whole list, nested)
L.extend([3, 4])   # → [1, 2, 3, 4]     each element individually
```
Also: `del L[i]` removes by index · `L.pop()` removes & **returns** last (or `pop(i)`) · `remove(x)` deletes first matching **value** · slicing works exactly like strings · `L.sort()` mutates in place vs `sorted(L)` returns new · **aliasing:** `B = A` points to the same list — `B = A.copy()` (or `A[:]`) clones.
- Nesting: `t = ((1.5, 2.7), [3.6, 4.1])` → `t[1]` grabs the list; tuples can hold mutable elements.

### Dictionaries `{key: value}`
- Keys: unique & immutable · values: anything
- `D['key']` access · `D['new'] = v` add · `del D['key']` · `'key' in D` → membership
- `D.keys()`, `D.values()`, `D.items()` (loop: `for k, v in D.items():`)

### Sets `{a, b, c}` — unordered, **no duplicates**
- `set([1,1,2])` → `{1, 2}` (dedup trick) · `.add()`, `.remove()`
- Math: `A & B` intersection · `A | B` union · `A.issubset(B)` / `A.issuperset(B)` · `A.difference(B)`

## 4. Module 3 — Programming Fundamentals

### Conditions & branching
- Comparisons `== != > < >= <=` return booleans · chain logic with `and or not`
- `if / elif / else` — indentation *is* the syntax

### Loops
- `for i in range(3):` → 0,1,2 · `range(start, stop, step)` — stop is **exclusive**
- `for i, item in enumerate(L):` → index + value together
- `while cond:` runs until false · `break` exits, `continue` skips iteration

### Functions
- `def f(param=default):` · `return` (no return → `None`) · `*args` collects extra positional args as a tuple
- **Scope:** a local variable **shadows** a global of the same name inside the function (quiz: local `a=100` wins over global `a=1`); `global` keyword to write globals
- ⚠ **Module 3 graded quiz Q9 miss:** "most appropriate add function for a scientific calculator" → the **type-validating version**: `if isinstance(num1,(int,float)) and isinstance(num2,(int,float)): return sum([num1,num2]) else: return None`. I picked the bare `return num1 + num2`. Lesson: in app-context questions, "most appropriate" = **robust/defensive**, not minimal.

### Exception handling
```python
try:
    file = open('data.csv', 'r')
    data = file.read()
except FileNotFoundError:
    print("File not found")
except ValueError:
    print("Invalid values")
else:
    print("Success")      # runs only if no exception
finally:
    file.close()          # always runs
```
- **Why specific except blocks beat one generic:** each error type gets a targeted message and appropriate action (graded-quiz answer) · Syntax errors are caught **before** execution; exceptions (ZeroDivisionError, FileNotFoundError…) occur **during**.

### Objects & classes
```python
class Circle(object):
    def __init__(self, radius, color):   # constructor
        self.radius = radius             # attributes
        self.color = color
    def add_radius(self, r):             # method
        self.radius += r
        return self.radius

c = Circle(10, "red")                    # instance
```
- `dir(obj)` lists attributes/methods · every instance carries its own attribute values

## 5. Module 4 — Working with Data

### Files with `open()`
| Mode | Meaning |
|---|---|
| `'r'` | read (default) |
| `'w'` | write — **overwrites** |
| `'a'` | append |
| `'r+'`/`'w+'`/`'a+'` | read + write variants |

```python
with open("file.txt", "r") as f:    # ⭐ auto-closes, even on error
    text  = f.read()                # whole file
    line  = f.readline()            # one line
    lines = f.readlines()           # list of lines
# loop: for line in f:
```
Writing: `f.write("line\n")` · copy pattern: read source with `'r'`, write target with `'w'`.

### Pandas
```python
import pandas as pd
df = pd.read_csv("data.csv")            # also read_excel, read_html
df.head()                                # first 5 rows
s  = df['col']                           # Series (1-D labeled)
d2 = df[['col1','col2']]                 # DataFrame subset
df.loc[0, 'col']    # label-based access
df.iloc[0, 2]       # integer-position access
df['col'].unique()                       # distinct values
df2 = df[df['year'] > 1985]              # boolean filtering
df.to_csv("out.csv", index=False)        # export
```
- **Series** = 1-D labeled array · **DataFrame** = 2-D table (dict of Series) · build from dict: `pd.DataFrame({'A': [1,2]})`

### NumPy
```python
import numpy as np
a = np.array([1, 2, 3])       # ndarray: fixed size, ONE dtype
a + b, a * 2, a ** 2           # vectorized element-wise ops (no loops)
np.dot(a, b)                   # dot product
a.mean(), a.max(), a.min(), a.std()
a.shape, a.ndim, a.size        # dimensions / rank / element count
np.linspace(-2, 2, num=9)      # evenly spaced samples
```
- 2-D: `A[1,2]` row 1 col 2 · matrix multiply `np.dot(A,B)` · why NumPy > lists: **speed (C-backed, vectorized) + memory + broadcasting**

## 6. Module 5 — APIs & Data Collection

### APIs & REST
- **API** = how two pieces of software talk; you see only inputs/outputs, not internals (Pandas itself is an API!)
- **REST APIs** communicate over HTTP: request → JSON response
- HTTP anatomy: URL = scheme + base + route · methods **GET** (params in URL), **POST** (data in body), PUT, DELETE
- `requests` library:
```python
import requests
r = requests.get(url, params={'name':'Joseph'}, headers={...})
r.status_code    # 200 OK · 404 not found
r.headers        # response metadata (Content-Type…)
r.json()         # parse JSON body → dict
requests.post(url, data=payload)   # payload in body, not URL
```

### Web scraping (BeautifulSoup)
```python
from bs4 import BeautifulSoup
import requests
html = requests.get(url).text
soup = BeautifulSoup(html, 'html.parser')
soup.find('table')                  # first match
soup.find_all('a')                  # all matches (list)
tag.text / tag.get('href') / tag['href']   # content & attributes
tag.parent · tag.next_sibling · soup.select('css selector')
```
- HTML tree: `<html>` → `<head>`/`<body>` → nested tags; tables = `<table>` → `<tr>` rows → `<td>` cells
- **Tables shortcut:** `pd.read_html(url)` → list of DataFrames, no soup needed ⭐
- Tool tiers: **BeautifulSoup** (parse static HTML) · **Scrapy** (crawling framework, large scale) · **Selenium** (JavaScript-rendered/dynamic pages)
- Workflow: HTTP request → retrieve page → parse HTML → extract → transform → store → automate

### File formats to recognize
CSV/TSV · JSON (`json` module: `load`/`dump`) · XML · XLSX — pandas has a `read_*` for each.

## 🎯 Interview Questions — JDA Path (Python for data work)

Python questions for analyst roles test practical data handling, not CS trivia. My edge: answer from a decade of production code, then bridge to analytics.

**Q1. What's the difference between a list and a tuple? When would you choose each?**
> Lists are mutable — append, remove, sort in place; tuples are immutable once created. I use tuples for fixed records that shouldn't change (coordinates, function returns with multiple values, dictionary keys) and lists for collections that grow or get reordered. Immutability is also a communication tool: it tells the next developer this data is not meant to be modified.

**Q2. Explain the difference between `append()` and `extend()`.**
> `append` adds its argument as a **single** element — pass it a list and you get a nested list. `extend` unpacks an iterable and adds each element individually. `[1,2].append([3,4])` → `[1,2,[3,4]]` but `extend` → `[1,2,3,4]`. It's a classic silent bug: the code runs fine, the structure is wrong, and everything downstream misbehaves.

**Q3. What's the difference between `/` and `//`?**
> `/` is true division and always returns a float — `1/2` is `0.5`. `//` is floor division — it rounds down to the nearest whole number, so `1//2` is `0`. It matters in analytics whenever you're bucketing or paginating: `//` for "how many complete groups," `/` for actual ratios. It's also the one question I got wrong on my IBM final exam — a good reminder that fundamentals deserve the same attention as advanced topics.

**Q4. What are mutable and immutable types in Python? Why does it matter?**
> Mutable: lists, dicts, sets — they change in place. Immutable: ints, floats, strings, tuples — operations create new objects. Two practical consequences: string methods like `.replace()` return new strings rather than editing, and **aliasing** — `B = A` on a list makes both names point to the same object, so mutating B silently changes A. For an independent copy you need `A.copy()`. Aliasing bugs in data pipelines are painful precisely because nothing errors.

**Q5. How do you handle errors when reading a file in Python?**
> Two layers. Structurally, `with open(...) as f:` guarantees the file closes even if something throws mid-read. For handling, specific `except` blocks — `FileNotFoundError` gets a different response than `ValueError` from malformed content — so each failure mode gets a targeted message and action instead of one generic "something broke." In pipelines I log the specific error and fail loudly; silent failures corrupt analyses.

**Q6. Pandas: what's the difference between `loc` and `iloc`?**
> `loc` selects by **label** — row index names and column names, like `df.loc[0, 'price']`. `iloc` selects by **integer position**, like `df.iloc[0, 2]` for the third column of the first row. The distinction bites when the index isn't a clean 0-N sequence — after filtering or setting a date index, position and label diverge, and using the wrong one returns valid-looking wrong data.

**Q7. What's a Series vs. a DataFrame?**
> A Series is a one-dimensional labeled array — one column with an index. A DataFrame is the two-dimensional table — essentially a dict of Series sharing an index. Selecting `df['col']` returns a Series; `df[['col']]` (double brackets) returns a one-column DataFrame. Knowing which one you're holding determines which methods are available.

**Q8. Why use NumPy arrays instead of Python lists for numerical work?**
> Three reasons: speed — operations are vectorized and executed in C, so `a * 2` beats looping by orders of magnitude; memory — one fixed dtype packed contiguously instead of scattered Python objects; and expressiveness — element-wise math, broadcasting, `np.dot` for linear algebra read like the underlying mathematics. Pandas is built on NumPy, so this efficiency underpins the whole analytics stack.

**Q9. How would you filter a DataFrame — say, rows where sales exceed 10,000?**
> Boolean masking: `df[df['sales'] > 10000]`. The inner expression produces a Series of True/False, and indexing with it keeps the True rows. Conditions combine with `&` and `|` with parentheses around each: `df[(df['sales'] > 10000) & (df['region'] == 'East')]`. Coming from SQL, I think of it as the WHERE clause of pandas.

**Q10. What is a REST API and how do you consume one in Python?**
> A REST API exposes data and operations over HTTP — you send a request to a URL with a method like GET or POST and typically receive JSON. In Python: `requests.get(url, params={...})`, check `status_code` (200 OK, 404 missing), then `response.json()` to parse into a dict. GET carries parameters in the URL; POST carries data in the request body. I've consumed and *built* APIs for a decade — including payment and reporting integrations in my freelance systems — so on the analyst side I'm equally comfortable pulling data programmatically as querying a database.

**Q11. How would you scrape data from a web page? What are the ethical considerations?**
> For static pages: `requests` to fetch, BeautifulSoup to parse — `find_all` for tags, then extract text and attributes. For tables specifically, `pandas.read_html` converts them straight to DataFrames in one line. For JavaScript-heavy pages, Selenium; for large-scale crawling, Scrapy. Ethics and legality first, though: check the site's terms and robots.txt, respect rate limits, prefer an official API when one exists, and never scrape personal data. In my IBM course I scraped and processed global GDP tables — fetch, extract with read_html, clean with NumPy rounding, export to CSV.

**Q12. Walk me through a small end-to-end Python data project you've done.**
> The GDP extraction project from my IBM certification: pull a country-GDP table from the web, extract it with pandas' read_html, clean the columns, convert values from millions to billions with proper rounding via NumPy, filter to the largest economies, and export a tidy CSV. Small, but it exercises the full analyst loop — acquire, wrangle, transform, deliver — the same loop as my larger projects, just compressed.

**Q13. When would you use a dictionary vs. a list?**
> Lists for ordered collections accessed by position; dictionaries for keyed lookup — when data has a natural identifier. Analytically, dicts shine for mappings (province → region), counters, and as the raw material for DataFrames — `pd.DataFrame(dict_of_columns)` is the most common construction. Under the hood dict lookup is O(1) versus scanning a list, which matters at data scale.

**Q14. What's the difference between a syntax error and an exception?**
> A syntax error is caught *before* the program runs — the parser rejects malformed code, like a missing colon. An exception happens *during* execution when something legal-looking goes wrong: dividing by zero, opening a missing file, converting "abc" to int. You can't try/except a syntax error, but exceptions are exactly what try/except exists for.

**Q15. You've used Python for 10 years as a developer — how does that change how you use it as an analyst?**
> Mostly in reliability and reach. My analysis code gets functions, error handling, and structure by habit, so it's rerunnable and shareable, not a one-off script. I'm not limited to what a GUI exports — if data lives behind an API, in HTML, or across systems, I can go get it. And having built the source systems — billing, sales, inventory — I know where data quality problems are born, which makes me faster at finding and fixing them downstream.
