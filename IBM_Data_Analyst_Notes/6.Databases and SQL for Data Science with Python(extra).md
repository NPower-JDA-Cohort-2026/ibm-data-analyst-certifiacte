## Overview
Bonus SQL module covering advanced techniques useful for Data Engineers: **views**, **stored procedures**, **transactions** (including ACID), and **JOIN** statements. Includes IBM Db2 and MySQL (phpMyAdmin) syntax, cheat sheets, and a nested-subquery example against Chicago census/crime tables.

---

## Key Concepts
- **View** — a dynamic, stored query definition that presents data from one or more base tables without storing a copy of the data
- **Stored procedure** — a set of SQL statements stored and executed on the server; send one call instead of many statements
- **Transaction** — a complete unit of work (one or more SQL statements)
- **ACID** — Atomic, Consistent, Isolated, Durable
- **JOIN** — combines rows from two or more tables based on a relationship between columns; usually a primary key in one table to a foreign key in another
- Join families: **inner join** and **outer join** (left, right, full); also **cross join** and **self join**

## Detailed Notes

### Views
A view is an alternative way of representing data that already exists in one or more tables. When you define a view, **only the definition is stored** — not the data it represents. The data remains in the base tables.

> [!note]
> You can write stored procedures in many languages: SQL PL, PL/SQL, Java, and C. Views themselves are SQL query definitions.

| Task | Syntax |
|---|---|
| Create | `CREATE VIEW view_name AS SELECT column1, column2, ... FROM table_name WHERE condition;` |
| Update | `CREATE OR REPLACE VIEW view_name AS SELECT ... FROM table_name WHERE condition;` |
| Drop | `DROP VIEW view_name;` |

**Create example**

```sql
CREATE VIEW EMPSALARY AS
SELECT EMP_ID, F_NAME, L_NAME, B_DATE, SEX, SALARY
FROM EMPLOYEES;
```

**Replace / update example** (join employees to jobs)

```sql
CREATE OR REPLACE VIEW EMPSALARY AS
SELECT EMP_ID, F_NAME, L_NAME, B_DATE, SEX, JOB_TITLE, MIN_SALARY, MAX_SALARY
FROM EMPLOYEES, JOBS
WHERE EMPLOYEES.JOB_ID = JOBS.JOB_IDENT;
```

**Drop**

```sql
DROP VIEW EMPSALARY;
```

Quiz-checked view definition for jobs with salary range 50,000–100,000:

```sql
CREATE VIEW JobSalaryRanges(Job, StartingSalary, MaximumSalary)
AS SELECT JOB_TITLE, MIN_SALARY, MAX_SALARY
FROM JOBS
WHERE MIN_SALARY >= 50000 AND MAX_SALARY <= 100000;
```

### Stored procedures
A stored procedure is prepared SQL saved on the database server so it can be reused. Benefits: **reuse of code**, **reduction in network traffic**, **improvement in performance**. Stored procedures can take **input parameters, output parameters, or both**.

The default statement terminator is `;`. To use a different terminator inside the procedure body:

| Platform | How to change terminator |
|---|---|
| IBM Db2 | `--#SET TERMINATOR @` then end the procedure with `@` |
| MySQL (phpMyAdmin) | `DELIMITER //` … `END //` then `DELIMITER ;` |

**Db2 — retrieve all rows from PETSALE**

```sql
--#SET TERMINATOR @
CREATE PROCEDURE RETRIEVE_ALL
LANGUAGE SQL
READS SQL DATA
DYNAMIC RESULT SETS 1
BEGIN
  DECLARE C1 CURSOR
  WITH RETURN FOR
  SELECT * FROM PETSALE;
  OPEN C1;
END
@
```

**MySQL — retrieve all rows from PETSALE**

```sql
DELIMITER //
CREATE PROCEDURE RETRIEVE_ALL()
BEGIN
  SELECT * FROM PETSALE;
END //
DELIMITER ;
```

### Transactions and ACID
A transaction is a complete unit of work (one or more SQL statements). An **ACID** transaction is one where all SQL statements complete successfully, or none at all.

| Letter | Meaning |
|---|---|
| **A**tomic | All changes must succeed, or none are applied |
| **C**onsistent | Data must be in a consistent state before and after the transaction |
| **I**solated | No other process can change the data while the transaction is running |
| **D**urable | Changes made by the transaction must persist |

| Command | Role |
|---|---|
| `COMMIT;` | Persist the changes |
| `ROLLBACK;` | Undo transactions that have not been saved |

Auto-commit is enabled by default, so rollbacks only work after you disable it:

- **MySQL:** `SET autocommit = 0;`
- **Db2 SQL Assistant:** gear icon → “On Success” → “commit after the last statement in the script” → save

**MySQL commit flow**

```sql
CREATE TABLE employee (
  ID INT,
  Name VARCHAR(20),
  City VARCHAR(20),
  Salary INT,
  Age INT
);

START TRANSACTION;

INSERT INTO employee (ID, Name, City, Salary, Age)
VALUES
  (1, 'Priyanka pal', 'Nasik', 36000, 21),
  (2, 'Riya chowdary', 'Bangalor', 82000, 29);

SELECT * FROM employee;
COMMIT;
```

**Rollback demo** (after disabling auto-commit)

```sql
INSERT INTO employee
VALUES (3, 'Swetha Tiwari', 'Kanpur', 38000, 38);

SELECT * FROM employee;
ROLLBACK;
SELECT * FROM employee;  -- row 3 is gone
```

Db2 uses the same `COMMIT` / `ROLLBACK` commands; the course example creates the `employee` table, inserts two rows, then `COMMIT`. For rollback, disable auto-commit in the SQL Assistant UI first, then insert a third row and `ROLLBACK`.

### Transactions inside stored procedures
Pattern: wrap money-movement updates in a procedure; on SQL exception, roll back; otherwise commit. Course example: debit Rose’s bank account twice (−200 then −300).

**Db2** (`TRANSACTION_ROSE`) — uses `DECLARE CONTINUE HANDLER FOR SQLEXCEPTION`, then `ROLLBACK WORK` or `COMMIT WORK` based on `retcode`:

```sql
--#SET TERMINATOR @
CREATE PROCEDURE TRANSACTION_ROSE
LANGUAGE SQL
MODIFIES SQL DATA
BEGIN
  DECLARE SQLCODE INTEGER DEFAULT 0;
  DECLARE retcode INTEGER DEFAULT 0;
  DECLARE CONTINUE HANDLER FOR SQLEXCEPTION
    SET retcode = SQLCODE;

  UPDATE BankAccounts
  SET Balance = Balance - 200
  WHERE AccountName = 'Rose';

  UPDATE BankAccounts
  SET Balance = Balance - 300
  WHERE AccountName = 'Rose';

  IF retcode < 0 THEN
    ROLLBACK WORK;
  ELSE
    COMMIT WORK;
  END IF;
END
@
```

**MySQL** — uses `DECLARE EXIT HANDLER FOR SQLEXCEPTION` with `ROLLBACK` + `RESIGNAL`, then `START TRANSACTION` … `COMMIT`:

```sql
DELIMITER //
CREATE PROCEDURE TRANSACTION_ROSE()
BEGIN
  DECLARE EXIT HANDLER FOR SQLEXCEPTION
  BEGIN
    ROLLBACK;
    RESIGNAL;
  END;

  START TRANSACTION;

  UPDATE BankAccounts
  SET Balance = Balance - 200
  WHERE AccountName = 'Rose';

  UPDATE BankAccounts
  SET Balance = Balance - 300
  WHERE AccountName = 'Rose';

  COMMIT;
END //
DELIMITER ;
```

### JOIN statements
A join combines rows from two or more tables based on a relationship between certain columns. To combine three or more tables, add more joins to the same statement. You can use an **alias** as shorthand for a table or column name.

You usually join the **primary key in one table to the foreign key in another**.

| Type | What it returns |
|---|---|
| **INNER JOIN** | Only rows where the join condition matches in both tables (most common) |
| **LEFT OUTER JOIN** | All inner-join rows **plus** unmatched rows from the **left** (first) table |
| **RIGHT OUTER JOIN** | All inner-join rows **plus** unmatched rows from the **right** (second) table |
| **FULL OUTER JOIN** | All rows from both tables; missing matches are `NULL` |
| **CROSS JOIN** | Every row of table1 paired with every row of table2 |
| **Self join** | A table joined to itself (usually via two aliases) |

Correct inner-join form (aliases required when column names collide):

```sql
SELECT * FROM EMPLOYEES e
INNER JOIN DEPARTMENTS d
  ON e.DEP_ID = d.DEP_ID;
```

#### Cheat Sheet: JOIN syntax

| Topic | Syntax | Example |
|---|---|---|
| Cross Join | `SELECT column_name(s) FROM table1 CROSS JOIN table2;` | `SELECT DEPT_ID_DEP, LOCT_ID FROM DEPARTMENTS CROSS JOIN LOCATIONS;` |
| Inner Join | `SELECT ... FROM table1 INNER JOIN table2 ON table1.col = table2.col;` | `SELECT E.F_NAME, E.L_NAME, JH.START_DATE FROM EMPLOYEES AS E INNER JOIN JOB_HISTORY AS JH ON E.EMP_ID = JH.EMPL_ID WHERE E.DEP_ID = '5';` |
| Left Outer Join | `SELECT ... FROM table1 LEFT OUTER JOIN table2 ON ...;` | `SELECT E.EMP_ID, E.L_NAME, E.DEP_ID, D.DEP_NAME FROM EMPLOYEES AS E LEFT OUTER JOIN DEPARTMENTS AS D ON E.DEP_ID = D.DEPT_ID_DEP;` |
| Right Outer Join | `SELECT ... FROM table1 RIGHT OUTER JOIN table2 ON ...;` | Same pattern with `RIGHT OUTER JOIN` |
| Full Outer Join | `SELECT ... FROM table1 FULL OUTER JOIN table2 ON ...;` | `SELECT E.F_NAME, E.L_NAME, D.DEP_NAME FROM EMPLOYEES AS E FULL OUTER JOIN DEPARTMENTS AS D ON E.DEP_ID = D.DEPT_ID_DEP;` |
| Self Join | `SELECT ... FROM table1 T1, table1 T2 WHERE condition;` | `SELECT B.* FROM EMPLOYEES A JOIN EMPLOYEES B ON A.MANAGER_ID = B.MANAGER_ID WHERE A.EMP_ID = 'E1001';` |

**MySQL does not support `FULL OUTER JOIN` natively.** Emulate it with `LEFT OUTER JOIN` `UNION` `RIGHT OUTER JOIN`:

```sql
SELECT E.F_NAME, E.L_NAME, D.DEP_NAME
FROM EMPLOYEES AS E
LEFT OUTER JOIN DEPARTMENTS AS D ON E.DEP_ID = D.DEPT_ID_DEP
UNION
SELECT E.F_NAME, E.L_NAME, D.DEP_NAME
FROM EMPLOYEES AS E
RIGHT OUTER JOIN DEPARTMENTS AS D ON E.DEP_ID = D.DEPT_ID_DEP;
```

### Nested subquery example (Chicago labs)
Community area name for the area with the most crimes:

```sql
%sql SELECT COMMUNITY_AREA_NAME
FROM CENSUS_DATA
WHERE COMMUNITY_AREA_NUMBER = (
  SELECT COMMUNITY_AREA_NUMBER
  FROM CHICAGO_CRIME_DATA
  GROUP BY COMMUNITY_AREA_NUMBER
  ORDER BY COUNT(*) DESC
  LIMIT 1
);
```

## Definitions
| Term | Definition |
|------|------------|
| View | Stored query definition that presents data from one or more base tables; the data itself is not stored in the view |
| Stored procedure | SQL (or other language) code saved on the server and executed there, reusable via a single call |
| Transaction | A complete unit of work made of one or more SQL statements |
| ACID | Atomic, Consistent, Isolated, Durable — properties of a reliable transaction |
| COMMIT | Persist uncommitted changes |
| ROLLBACK | Undo uncommitted changes |
| Inner join | Returns only matching rows from both tables |
| Outer join | Inner-join matches plus unmatched rows from left, right, or both tables |
| Cross join | Cartesian product of two tables |
| Self join | A table joined to itself |
| Alias | Shorthand name for a table or column in a query |

---

## Important Points
- Views store the **definition**, not a snapshot of the data.
- Stored procedures can use input parameters, output parameters, or both.
- Stored-procedure benefits are all three: reuse, less network traffic, better performance.
- ACID = Atomic, Consistent, Isolated, Durable — not “Initiated/Duplicated” or similar distractors.
- Disable auto-commit before you can demonstrate `ROLLBACK`.
- Joins are usually **PK ↔ FK**, not “any column” and not PK-to-PK by default.
- Right outer join = inner matches + unmatched rows from the **second** table.
- Full outer join = all rows from both tables.
- MySQL full outer join = `LEFT OUTER JOIN … UNION … RIGHT OUTER JOIN`.

## Tips & Best Practices
- Qualify join columns with table aliases (`e.DEP_ID = d.DEP_ID`) so identical names do not collide.
- Change the statement terminator (`@` or `//`) before writing a procedure that contains `;` inside `BEGIN…END`.
- On MySQL, `START TRANSACTION` before the work you may need to roll back.
- Add extra `JOIN` clauses rather than nested one-off queries when combining three or more tables — unless a subquery is the clearer tool (as in the Chicago “max crime area” example).

## Common Mistakes
> [!warning]
> Treating a view as an independent copy of table data. Only the view definition is stored; data lives in the base tables.

> [!warning]
> Creating a view with `WHERE SALARY > 50000` when the table has `MIN_SALARY` / `MAX_SALARY` columns — the valid range filter is `MIN_SALARY >= 50000 AND MAX_SALARY <= 100000`.

> [!warning]
> Writing `SELECT * FROM EMPLOYEES INNER JOIN DEPARTMENTS ON DEP_ID = DEP_ID` — ambiguous columns. Use aliases: `ON e.DEP_ID = d.DEP_ID`.

> [!warning]
> Expecting `ROLLBACK` to undo work while auto-commit is still on.

> [!warning]
> Using `FULL OUTER JOIN` on MySQL — use `UNION` of left and right outer joins instead.

## Interview Questions

### Beginner
1. **Q: What is a SQL view, and is the data stored in it?**
   A: A view is a stored query definition that presents data from one or more tables. Only the definition is stored; the data remains in the base tables.
2. **Q: What does ACID stand for?**
   A: Atomic, Consistent, Isolated, Durable.
3. **Q: What is the difference between COMMIT and ROLLBACK?**
   A: COMMIT persists the transaction’s changes. ROLLBACK undoes uncommitted changes.
4. **Q: What is a stored procedure?**
   A: A set of SQL (or other language) statements stored and executed on the database server so the client can send one call instead of many statements.
5. **Q: What is an INNER JOIN?**
   A: It returns only rows where the join condition matches in both tables.

### Intermediate
1. **Q: Why use a stored procedure instead of sending several SQL statements from the application?**
   A: Reuse of code, less network traffic, and better performance because the logic runs on the server.
2. **Q: How do left, right, and full outer joins differ?**
   A: Left keeps all rows from the first table (unmatched right-side columns are NULL). Right keeps all rows from the second table. Full keeps all rows from both.
3. **Q: How do you usually decide which columns to join?**
   A: Join the primary key of one table to the foreign key of the other.
4. **Q: How do you emulate a full outer join in MySQL?**
   A: `LEFT OUTER JOIN … UNION … RIGHT OUTER JOIN` on the same condition.
5. **Q: What parameters can a stored procedure take?**
   A: Input, output, or both.

### Advanced
1. **Q: Walk through how you would make a two-step bank transfer atomic in SQL.**
   A: Put both `UPDATE`s in one transaction / stored procedure. On SQL exception, `ROLLBACK`; otherwise `COMMIT`. Db2 example uses a continue handler and `retcode`; MySQL uses an exit handler with `ROLLBACK` and `RESIGNAL`.
2. **Q: Why might `ROLLBACK` appear to do nothing in a lab?**
   A: Auto-commit is on by default. Disable it (`SET autocommit = 0` in MySQL, or change Db2 SQL Assistant “On Success” to commit only after the last statement).
3. **Q: Write a query that returns the census community area with the most crimes.**
   A: Nested subquery: group `CHICAGO_CRIME_DATA` by `COMMUNITY_AREA_NUMBER`, `ORDER BY COUNT(*) DESC LIMIT 1`, then look up `COMMUNITY_AREA_NAME` in `CENSUS_DATA`.
4. **Q: `ON DEP_ID = DEP_ID` in an inner join of EMPLOYEES and DEPARTMENTS — what’s wrong?**
   A: The column name exists in both tables and is ambiguous. Alias the tables and qualify: `e.DEP_ID = d.DEP_ID`.
5. **Q: How do you combine data from three or more tables?**
   A: Add additional JOIN clauses to the same SELECT; you are not limited to two tables.
